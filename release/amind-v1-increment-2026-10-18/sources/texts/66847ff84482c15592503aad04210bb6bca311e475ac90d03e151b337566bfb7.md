Data collection

Sample

We collected a stratified sample of Claude.ai Free, Pro, and Max conversations across three models (Claude Sonnet 4.6, Claude Opus 4.6, Claude Opus 4.7) and 20 languages over a two-week period in May 2026. We aimed for 5,333 conversations in each of the 60 model-language combinations. A few combinations were below that threshold because some languages had less traffic on some models during the sampling window. These were Arabic conversations with Opus 4.6 (n=5,156) and Opus 4.7 (n=3,565), Hindi conversations with Opus 4.6 (n=1,174), and Indonesian conversations with Opus 4.6 (n=5,068) and Opus 4.7 (n=1,537). We restricted the sample to conversations that involve subjective judgment on Claude’s part (53.2% of all conversations), meaning conversations where the response depends on weighing considerations rather than retrieving facts or executing a fixed task. The exact criterion is in the subjectivity screener prompt in the Prompt section.

Value taxonomy

We started from the 3,307 values identified in Values in the Wild. To make the labeling task manageable, we clustered those into 339 higher-level values. We did this by clustering text embeddings of the original values into groups, then manually reviewing and refining the groups until each one read as a single coherent value.

Labeling conversations

What we labeled

For each conversation, we used Claude (via our privacy-preserving analysis tool) to record:

●​ Model-expressed values. Which of the 339 values Claude expressed in its responses, on a 1-5 salience scale. We treat a value as “expressed” when it scores 3 or higher (i.e., is actively present, a strong driver of the conversation, or a central value). ●​ User-expressed values. Which of the 339 values the user expressed, on the same salience scale. ●​ Task. A one-sentence description of what the user is asking Claude to do, written by the analysis tool and then clustered into task categories.

Validation

We validated the analysis tool and its prompts in three ways. First, we manually reviewed labels on conversations from sources we are permitted to read directly, including the public WildChat dataset, conversations where users had given feedback, and synthetic conversations we generated with Claude.1 Second, we checked that the labels did not change substantially when we slightly reworded the prompt or changed the sampling temperature. Third, we tested whether the analysis tool’s output depends on which language a conversation is written in, since the analysis tool itself uses a Claude model and might carry the same language-conditioned tendencies we are trying to measure. To do so, we translated 800 real conversations into eight of the languages (Arabic, Dutch, English, German, Hindi, Japanese, Korean, and Spanish) and ran the same Claude-based analysis tool on every copy to label the values Claude expresses in the conversations. Since the content is held fixed, any differences in the labeled values reflect language bias. Claude shows some bias when labeling, but it's small. Only 11 of 339 values expressed by Claude are affected, and the largest effect is an order of magnitude smaller than the corresponding cross-language difference in the main analysis. When we account for this bias, the headline results remain unchanged.

Finding the four axes

Approach

Main method: Hellinger PCA

The 18 most frequent values (for example, helpfulness, clarity, and following instructions) show up in at least 80% of all conversations, and are consistently prevalent across languages. Because we're interested in value variation across conversations, we removed these frequent values from the analysis and focused on the values that varied more. These near-universal values would otherwise dominate the analysis without telling us anything about variation. We subsequently dropped every conversation for which there were no associated values remaining (~2–4% conversations per language). We then normalized each conversation’s row so the values Claude expressed summed to one and took the square root of each proportion. This transformation puts all conversations on a common scale regardless of how many values they expressed, and the square root makes ordinary distance between rows match the Hellinger distance between value distributions, which is a way to compare proportional data. We also mean-normalized the columns of this matrix. Next, we removed the part of the variation that is explained by task, topic, and the user’s expressed values by regressing every column on those covariates and keeping only the residuals. This step accounted for 31.7% of the total variation.2 After regressing out the covariates, any remaining variation between conversations is not due to topic (up to additive, linear effects and the granularity of the topics) but instead other differences in how Claude responded. We then ran principal component analysis on the residual matrix. Based on the scree plot, we kept four components. We rotated those four components using varimax, which keeps the four axes orthogonal to each other while maximizing the spread of the squared value loadings so that each axis is driven by a smaller and more interpretable set of values.

Robustness check: logistic factor model

As a robustness check, we fit a logistic factor model that predicts whether each value is expressed in each conversation as a function of two things: the covariates (task, topic, user values) and a small number of latent axes. The model is logistic, so it works directly on the 0/1 expression data without the proportion transformation. This method naturally separated out one axis that roughly captures how many values the analysis tool found in a conversation. After setting that axis aside, rotating the next four gave: (1) warmth vs. rigor, (2) excellence vs. restraint, (3) deference vs. caution, and (4) positivity vs. honesty. Axes 1, 3, and 4 here correspond roughly to the Warmth vs. Rigor, Deference vs. Caution, and Candor vs. Execution axes from the blog post, respectively. The main difference is the second axis (excellence vs. restraint) which is not directly analogous to the remaining main method axis Depth vs. Brevity.

Validation

We checked the axes against three criteria. Significance. The first four components each explain more variance than would be expected from randomly shuffled data with row and column sums preserved (Horn’s parallel analysis). Stability. We reran the analysis on 50 bootstrap resamples of the conversations. Across all 50 reruns, every axis matched the original with a congruence coefficient of 1.0 at the 5th percentile, well above the 0.95 threshold usually taken to mean that the bootstraps are finding essentially the same axes.

Value profiles for models and languages

To get a model’s position on an axis, we averaged the axis coordinates of all conversations from that model. We did the same for each language. Because rotating the axes can introduce correlations between the per-conversation coordinates, we checked those correlations. The largest are 0.27, between axes 1 and 4, and 0.25, between axes 1 and 3, with the rest at most 0.15.

Distinctive behaviors

To identify which individual values are distinctive to a model version or language, we fit a separate logistic regression model for each of the 339 values. The model asks: holding task, topic, and user-expressed values fixed, does this model version (or this language) express this value more often than the average of the others? Concretely, we fit a logistic regression model of whether the value was expressed on indicators for model version, language, task category, topic category, and the user’s expressed values. The model version and language effects are read as differences from the across-group average. A coefficient significantly greater than 0 (equivalently, an odds ratio above 1) means that value is over-expressed for that model version or language compared to the others. This controlling for covariates handles additive differences in log-odds. It does not handle interactions between covariates and other nonlinear effects.

To turn each model's distinctive values into the behavior labels shown in the main figures, we used two steps. First, whenever the analysis tool tagged a value in a conversation, it also wrote a one-sentence reason describing what Claude did to reflect that value. We summarized those reasons across all conversations to produce a short behavioral description for each value. For example, the value ‘intellectual honesty’ is tagged when Claude acknowledges uncertainty, corrects errors, and pushes back on false premises. Second, for each model, we took its most distinctive values along with their behavioral descriptions and had Claude group them into a small number of broader behaviors, giving each group a short label. We performed the same process to produce Claude’s distinctive behaviors when conversing in each language.

Limitations

The privacy-preserving analysis tool is built on Claude. Our privacy-preserving analysis tool is itself a Claude model, so it may share some of the same language-conditioned tendencies we are trying to measure. It also uses a coarser set of 339 values rather than the full 3,307 from Values in the Wild, which makes the analysis less granular. On transcripts shared with Anthropic through the feedback button, we found the analysis tool exhibits some biases, such as labeling warmth-related values more often when responses contain emojis or kinship terms. The values are underspecified. We do not prescribe definitions for specific values (e.g., we do not explicitly define “rigor” in our privacy-preserving analysis tool prompt), so the interpretation of which values are reflected in Claude's behavior is left to the Claude-based analysis tool. We measure value presence, not value strength. Our analysis considers only whether a value was reflected in a conversation, not how strongly or how often it was expressed in the conversation. Differences in user requests across languages. Because we observe real usage rather than testing the same prompt in every language, differences in how users converse with Claude across languages can show up as language effects. Controlling for task, topic, and user values reduces this but does not eliminate it. Controlling is linear and additive only. Regressing out task, topic, and user values removes only the variation those covariates linearly and additively explain. Interaction effects (for

Controlling for user values may distort our measurements. A user's expressed values can themselves be influenced by which model and language they are using. Controlling for a user’s expressed values could therefore exaggerate apparent links between language and Claude's expressed values. We did not control for the number of salient values. The number of values expressed in a conversation may be influenced by which values Claude expresses, so we did not project it out before applying dimensionality reduction. We found that the number of values Claude expresses in a conversation is only weakly correlated with the axes. The axes are only correlational. They describe how the relative proportions of values vary across conversations. They are not causal effects of a model or language, and they do not describe patterns within a single conversation. We also interpret the axes based on the values that contribute the most, but the axes also capture small contributions from other values. The axes tend to be bipolar by construction. Because each conversation's values are normalized to proportions, expressing more of one value group mechanically deflates the proportion of others. The value groups at opposite ends of an axis are therefore not guaranteed to be true behavioral opposites. However, we verify within conversations that the proportions of expressed values falling in each pole's top-five contributors are negatively correlated for the first two axes. The axes capture only part of the variation. The four axes are shaped by the window of data collection and the limited set of models and languages we consider. They account for only 15% of the total variance in values across conversations (after regressing out the conversation task, topic, and user-expressed values), so more granular differences between models and languages fall outside what they capture.

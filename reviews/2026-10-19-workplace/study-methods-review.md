# Outcome-blind methods review

Reviewed only the protocol, fingerprints/manifests, isolation description, main plan, citation contract/preregistration/README, capture/app-grading scripts, repair-plan builder and selected-repair manifest. No trial answers, runs, grades or outcome scores were inspected. This is a static design audit; it does not attest that every execution obeyed the design.

**Blocking failures:** None established in the inspected design. The protocol, measurement-manifest and snapshot hashes match their recorded fingerprints; the runner matches the main-plan hash. All 42 planned skill inventories match their assigned snapshot, and starter inventories, public tests and task prompts are identical within each task. Main counts are 12 engineering, 12 evaluation and 18 citation executions, with three repetitions per task/arm. Freeze chronology is asserted by the saved metadata, rather than independently timestamp-attested.

**Reporting corrections required:**

- `scripts/grade_amind_workplace_apps.py:32` always emits `independent_tasks: 4`, including for a repair plan containing at most two selected tasks. Derive the actual distinct task count from the relevant plan when reporting reserved validation; the main app plan has four tasks total and two per axis.
- Agreed reporting disposition: retain the frozen wrapper and its raw output, then derive corrected task counts from each plan in a separate summary. The final report will describe app treatment effects at package-bundle level and label reserved repair evidence as validation on reused tasks against historical current references. This disposition was communicated by the parent; its later execution was not inspected in this audit.
- A harness exception can leave a run directory without `capture.json`: the directory is created before validation/launch, exceptions propagate, and `--remaining` excludes existing directories (`run_amind_workplace_trials.py:83–90,133–142`). The grading script also stops on a grader exception. Final accounting must start from every planned ID and explicitly retain missing capture/grader records as unresolved failures. Do not infer completion from directory existence, silently drop rows, rerun them outside the fixed budget, or turn unexecuted answers into substantive zeros. This is a conditional implementation risk, not evidence that it occurred.

**Disclosure limits and interpretation:**

- The independent unit is the curated task family: two per axis. Three repetitions estimate variation for the same unchanged task; the repetition index is not a shared seed or an independent task. Fourteen app probes and five citation criteria are correlated checks, not extra samples. Keep per-task means/ranges, completion denominators and hard-invariant failures visible; do not pool unlike score scales across axes or make population/significance claims. Report semantic means with their valid-capture count alongside all planned execution statuses.
- Both app skill packages are supplied and changed together (`run_amind_workplace_trials.py:73–77,92`). These trials compare an old/current package environment on engineering or evaluation tasks; they do not isolate the causal contribution of just the named skill, its prose, or one helper. The fixed prompts explicitly request investigation, verification and complete citation passages, so conclusions concern performance under that scaffold.
- The citation inventory supports the intended contrasts: before→docs changes only `SKILL.md` and `references/evidence-policy.md`; docs→full changes `current-status.jsonl` and `manifest.json`. SQLite/passages are fixed. Preserve the registered task-specific primary outcomes, P2+P4+P5 and L1+L4+L5, as well as totals. Registry evidence, primary support gaps, false facts, reasonable unknowns and over-refusal remain distinct. Supplementary document-opening context available to the grader is not proof the target read it. Anonymous control agreement is AI calibration on eight constructed answers, not human validation or a reliable estimate of grading accuracy.
- Isolation is a useful path-deny envelope with checked canaries and portable app grading. Target execution still uses `(allow default)` without OS network denial (`run_amind_workplace_trials.py:25–35`); native web/apps/plugins/MCP are disabled and shell networking is forbidden by instruction. Therefore claim restricted sources and denied protected paths, not complete host isolation or enforced target egress isolation. The actual served model is unverified. Deterministic rotated ordering and concurrent execution reduce some order imbalance but do not supply randomization, stable-serving attestation or a clean causal latency comparison. Native token/elapsed diagnostics support descriptive overhead analysis, not dollar savings.
- Reserved repair calls are three repaired-candidate repetitions on each of at most two reused task families, compared with historical current-arm captures (`prepare_repair_plan.py`). They have no fresh contemporaneous baseline, common seed or untouched holdout. Label them selected after-discovery validation and keep them outside the original 42-run comparison. The selected-repair manifest states selection used independent offline diagnostics before primary outcomes; preserve that provenance rather than describing the fixes as discovered by these trials. App repair tasks do not require importing the repaired helpers, so a reserved task success alone cannot establish that a particular helper defect is fixed; direct regression evidence and package-level trial evidence answer different questions. The manifest's product-test counts were not independently audited here.

No frozen measurement files were changed by this review.

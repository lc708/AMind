## 工具配置偏差与补充确认

主轮的空 `mcp_servers = {}` 没有清除主机继承的 MCP：实际目录仍有 Node 和文档服务。3 次引用执行 W017／W018／W038 共 31 次 Node 调用；全部命令审计中未见越界取材，Node 代码观察到的读写也限于自身目录，但这不能证明完整 OS 路径隔离。原生 MCP canary 在执行探针前因 `sandbox_apply: Operation not permitted` 失败；不能据此宣称已绕过或已验证外层 Seatbelt。

主轮所有 42 次的工具目录都不满足预期的 MCP 禁用条件；其中 39 次未观察到 MCP 使用，应用 24 次均未用。原分母保留 42／18，不把未观察到使用称作严格隔离。后验排除三次使用记录时，政策修订前仍为 2,2,2，只改说明和完整修订均剩 5,5；研究各剩余答复仍为 5。因而新规则相对修订前的方向未依赖这三次记录，但**策展理由相对只改说明的独立增量收益尚未建立**，唯一一分差来自偏差运行及标签解释边界。

已改用逐服务器 `enabled=false`，有效配置清单确认全部关闭；该配置方式有[OpenAI 官方说明](https://learn.chatgpt.com/docs/extend/mcp#other-configuration-options)。新增预检已实际拒绝原继承配置、接受显式关闭配置，详见[反向控制](validation/runtime-inventory-original-rejected.json)及[有效清单](validation/runtime-inventory-corrected-accepted.json)。原主机配置未改。预留 6 次改为：修复版持久化应用 3 次，对照历史当前版；另对上述 3 个引用配置各作一次严格关闭 MCP 的确认。引用正文和规则不再变动。两类均为后验复用任务确认，没有替换原主轮，也不是全新保留集。参考[工具修正](runtime-correction.json)、[MCP canary](runtime-mcp-canary.json)、[补测协议](repair-phase-protocol.json)。

## 已修复的产品问题

五类实现缺陷在查看主轮答案之前独立发现，修复源先冻结，主轮仍使用原 0.3.1／0.4.1：

| 问题 | 修复及实际验证边界 |
|---|---|
| 同一 SQLite 的符号链接路径产生不同协调锁，可能提前核对活跃工作 | 统一真实路径身份；文件及目录别名和真实进程崩溃控制通过。没有承诺硬链接或分布式通用锁。 |
| `completed` 同时含非 null 值的 error／incomplete_details，工具循环仍可能派发 | 展示与派发共用终态校验，包括空对象；矛盾输入零 validate／authorize／effect，健康 nullable 字段和旧原始消息保留。 |
| 迟到 handler 结果覆盖外部核对的已确认结果 | 仅 pending 状态允许提交；冲突显式要求核对，匹配结果可复用。未承诺外部系统 exactly-once。 |
| 报告信任未绑定 `_state.json`，可改变人口、指标或重复次数 | schema2 按绑定比较身份校验全部 split、指标、rep，漂移在聚合前拒绝；legacy 明示未验证。 |
| 结果／调用日志能越过绑定集合或 rep 范围 | 每条结果和 started／finished 都校验集合及严格整数范围；合法部分完成继续保留，已发生费用不因失败消失。 |

首次工程补丁曾把展示 schema 校验强加于旧 raw message，完整检查发现回归后改为共享终态校验，原历史夹具未改。修前、初次补丁失败、最终成功记录均保留；没有只留成功摘要。

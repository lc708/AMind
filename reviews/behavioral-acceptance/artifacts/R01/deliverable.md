# 副作用工具的恢复与取消

已实现一个仅使用 Python 标准库和本地 SQLite 的可运行恢复路径。保留题目原始操作 `t1 / job1 / c1 / charge / amount=20`；不解释金额的货币或计量单位。真实子进程在模拟远端已完成 `op1`、本地尚未写入成功时退出；重启后通过查询恢复成功，重复调用仍只有一笔模拟扣款。

## 文件与运行

- `recovery.py`：授权与参数校验、持久化状态机、重试预算、取消、只读对账，以及独立持久化的远端模拟器。
- `demo.py`：读取原始 `task.json`，完整执行指定崩溃时间线；进程退出码为 73。
- `test_recovery.py`：21 项行为测试，包括真实子进程重启。
- `verify.py`：执行检查并保存日志、演示结果和执行记录。
- `evidence/final-crash-recovery/report.json`：最终版本的崩溃恢复证据；同目录两个数据库分别代表应用账本与远端服务。
- `evidence/unittest.log`、`evidence/demo.log`：实际检查输出。
- `execution.json`：读取文件、执行命令、工具调用计数、约束与制品哈希。

在本任务目录运行：

```sh
python3 -m unittest -v
python3 demo.py --out evidence/another-fresh-run
```

演示要求输出目录尚无数据库，避免覆盖证据。无需安装依赖或配置密钥。

## 执行契约

这是规则确定的单工具执行器，无需引入模型或 agent 循环。应用代码传入受信任 `Context`，包含已认证的租户、任务及发票所有权判断；工具参数不能授予自身权限。每次执行、重放、取消和复核都重新授权，并严格验证 `charge` 与正整数金额。题目没有发票 ID，因此保留其“已认证租户拥有发票”的前提，以应用上下文的布尔事实建模；真实发票查询与身份认证不在本地夹具中伪造为生产能力。

幂等键是规范化 `[tenant, task, call_id]` 的 SHA-256，远端与本地使用同一键。完整请求另行持久化；相同键更换金额或参数立即报冲突。新 `call_id` 表示新业务操作，所以请求方必须在重投时保留原调用标识。

| 状态 | 含义与下一步 |
| --- | --- |
| `ready` | 尚未预留派发；可以取消为 `cancelled`。 |
| `unknown` | 已持久化派发意图，尚无可信的最终结果；先查询远端。 |
| `succeeded` | 有绑定原始请求与幂等键的成功回执，保存 `operation_id`；重放返回已保存结果。 |
| `failed` | 适配器明确保证“未发生副作用”的拒绝；不自动重试。 |
| `cancelled` | 取消发生于任何派发预留之前；没有发起扣款。 |

`cancel_requested` 是独立且持久化的事实，不替代业务结果。所有持久化事务使用 SQLite `BEGIN IMMEDIATE`、WAL 和 `synchronous=FULL`。

## 原始崩溃路径

1. 本地提交 `unknown` 与派发预算，然后以稳定幂等键调用远端。
2. 模拟远端独立提交 `op1`，进程在提交本地成功前真实退出。
3. 同一事件重投时，先验证身份和请求一致性，再调用 `lookup_operation`。
4. 查询回执包含相同键、原始参数、成功状态与 `op1` 后，提交本地成功及查询证据。
5. 后续重投直接返回本地记录；不再查询或扣款。

查询返回“不存在”不证明先前请求失败。允许再次写入时仍使用原幂等键，即使查询暂时看不到成功，模拟远端也会返回原 `op1`，不会产生第二笔扣款。

## 重试与取消

移除了“任何异常立即重试”的策略。`execute()` 执行一个步骤；恢复步骤只查询，不紧接着扣款。成功查询但没有发现操作后，由调用方在持久化 `next_at` 到期时调用 `retry()`。写超时和查询超时保留未知状态；意外异常或不匹配回执停止自动操作并要求复核。

默认自动预算为最多 3 次写入预留、8 次远端调用预留；退避为 1、2、4、8、16 秒并封顶，单次适配器超时参数为 2 秒。不在执行器内等待或循环重试。预算在调用前持久化，所以崩溃也消耗预算。固定时钟使测试可复现；生产调度器及真正的 I/O 超时由集成端实现。

- 取消先于派发预留：持久化 `cancelled`，重启和重复调用都不会扣款。
- 取消发生于派发之后或远端执行期间：阻止后续写入，但继续查询已有操作；若发现成功，记录 `succeeded` 并保留取消标志。
- 取消后查询仍未发现操作：保留 `unknown`，停止自动派发，不宣称已撤销。
- `review()` 提供显式只读复核，对已暂停的未知结果最多再查询 3 次，预算跨重启持久化；它不能绕过自动退避、清除取消或重置写入预算。后续出现的成功回执可以恢复结果。超过预算仍未知时保留记录，交由运维核查远端状态。

取消与派发预留共用事务顺序。已经预留的请求可能继续到达远端；本地取消不等于远端撤销，也不会自动退款。

## 实际验证

初次执行 `python3 -m unittest -v`：18 项全部通过。随后补充取消后的只读复核、持久化复核预算与禁止绕过退避，最终通过 `python3 verify.py` 再次执行同一测试命令：21 项全部通过；完整结果保存在日志与 `execution.json`。

最终演示实际运行 `python3 demo.py --out evidence/final-crash-recovery`：子进程退出 73，父进程成功退出 0；恢复前为 `unknown`，查询后为 `succeeded / op1`；模拟扣款数为 1，恢复过程新增扣款请求为 0、查询请求为 1。重复交付返回完全相同的记录。

测试覆盖原始崩溃、重复请求、参数冲突、跨租户/任务/调用键隔离、未授权与畸形参数、取消前/中/后行为、取消与重试之间的竞态、成功响应丢失、查询超时、查询暂时返回不存在、明确拒绝、预算耗尽及错误回执。原始 `task.json` 与技能源均未修改。

## 证据范围与限制

所有远端结果均为固定本地模拟；进程退出、SQLite 提交、重启及测试断言是真实执行。没有目标模型、支付服务、网络、凭据、部署或外部副作用，也没有模型质量比较。

远端幂等键保留期限、查询一致性、真实回执可信度、生产身份系统及服务端超时均未验证。重试的安全性依赖远端在恢复窗口内可靠地执行同键去重；幂等记录过期时应停止写重试并人工核查。SQLite 方案面向本地单任务执行，未验证多主机并发、存储故障或生产调度。调用方必须持久化并执行 `next_at` 调度，使用可跨进程解释的时钟。源码只传递超时参数，未声称能强制终止真实远端请求。原始方案是按远端证据恢复，不能宣称跨系统“恰好一次”。

回退可停止调用此本地执行器；保留账本和幂等键，不清库、不更换键后重试，也不要恢复原先的盲目异常重试策略。

# 提示词审查与最小补丁

已提供一处句子替换的补丁，消除“没有工具”与当前工具清单的冲突。支付事故规则、`RESULT:` 协议和恰好三句话的要求全部原样保留。11 个本地测试通过；31 个固定轨迹/输出用例的判定均符合预期。没有调用目标模型或支付服务，尚未测得模型质量、成本或延迟的改善。

## 执行合同与证据范围

- 输入依据：`task.json:5` 的原始提示词、`:6–9` 的工具清单、`:10–16` 的来源与目标约束。原始文件未修改，`input.sha256` 保存其摘要，`baseline.prompt.txt` 按原始提示词逐字符保存。
- 目标仍为当前配置的模型及原提供商；输入没有实际模型 ID、SDK、应用入口、工具 schema 或生产解析代码，因此没有推断或修改这些配置。
- 编辑范围：本任务目录内的补丁、固定夹具、可运行检查与交付文档。仅做本地离线检查；模型调用预算为 0。
- 质量门槛：只替换过时的能力声明，所有其他原始约束不变；保留重试前检查和禁止重复扣款；保留第 0 个字符开始的七字符前缀与三句话要求。
- `rendered_baseline.json` 与 `rendered_candidate.json` 展示固定输入的组装结果，包含同一工具名清单和目标策略。它们是合成的输入表示，不是生产请求、真实调用点或已验证的提供商 API 格式。

## 逐项判断

| --- | --- | --- |

## 唯一建议修改

```diff
- You have no tools.
+ You have the tools lookup_payment and charge_once.
```

完整候选见 `candidate.prompt.txt`，逐行补丁见 `prompt.patch`：

```text
IMPORTANT: always check payment status before retrying. NEVER charge twice. You have the tools lookup_payment and charge_once. Begin every answer with RESULT: and output exactly three sentences.
```

这个改动纠正环境事实，没有增加新业务规则，也没有删除不确定来源的要求。模型是否因此更可靠，当前证据不足；不把文本修正或用例通过率当成模型行为收益。

## 可运行回归与实际结果

在本任务目录执行：

```sh
python3 -m unittest -v test_local_contract.py
python3 local_contract.py
```

实际结果：第一条命令报告 `Ran 11 tests in 0.002s`、`OK`；第二条输出 `{"case_count": 31, "oracle_mismatches": 0, "model_calls": 0}`。两条命令所在进程退出码为 0。`offline_report.json` 保存逐例结果、输入/代码摘要和证据限制。

- 23 个支付轨迹用例：9 个符合本地合同的轨迹被接受，14 个违反合同的轨迹被拒绝。覆盖普通首次扣款、已支付重试、明确未扣款重试、查询失败/超时、未知和处理中状态、重复扣款、支付 ID 错配、缺失/更换幂等键，以及扣款超时后的重新查询。
- 8 个输出用例：3 个简单的三句话输出被接受，5 个缺失/错误/移位前缀或句数错误的输出被拒绝。
- 额外静态测试检查原始输入摘要、唯一句子替换、支付规则逐字保留、前缀/句数保留、工具与目标策略不变；还故意删除各项原始约束，确认补丁范围检查会失败。

`local_contract.py` 是固定轨迹的校验器，不会驱动代理或执行支付。用例中的状态名称、事件字段、稳定幂等键与“同一支付明确未扣款”的含义均是显式本地假设，不是生产工具 schema。超时后不允许无新查询直接重试；再次查询确认未扣款时，本地合同要求复用原幂等键。工具叫作 `charge_once` 本身不能证明后台有幂等保障。

句数校验仅覆盖此次简单英语固定语料；缩写、小数、引用或其他语言的分句没有验证。测试响应与轨迹均为人工固定夹具，不是模型生成样本。没有独立留出集、真实应用测量或目标模型对比，也没有 token/模型延迟数据；报告里的本地耗时不代表模型耗时。

## 采用与回滚

当前建议可作为最小待集成补丁审阅。实际采用时，在生产提示词来源替换同一句，并确认真实请求包含这两个工具、真实消费端仍只移除同一前缀。将这些事故与协议用例接到真实应用入口，使用隔离支付替身验证工具分派与后端幂等；真实模型比较需要另行授权并保持模型、提供商、数据和判定标准一致。本次没有进行该比较。

如发现集成回归，可用 `baseline.prompt.txt` 恢复原始提示词；其中旧能力声明与工具清单的矛盾也会随之恢复，因此它只是可追踪的回滚基线。无需部署、凭证或外部操作即可复现当前离线检查。

本次固定数据的已知及估算费用小计为 **$0.0069**；完整费用未知。候选质量点估计比基线低 **0.01（1 个百分点）**，在允许损失 **0.02** 以内，但缺少配对样本与置信区间，不能据此证明质量非劣，也没有候选费用来证明降本。

成功 application 的计算为：

```
未缓存输入：(1000 - 900) × 10 / 1,000,000 = $0.0010
缓存输入： 900 × 1 / 1,000,000           = $0.0009
输出：     100 × 20 / 1,000,000          = $0.0020
合计：                                     $0.0039
```

采用已归一化的计数语义：`cached_input_tokens` 是 `input_tokens` 的子集；`reasoning_tokens=80` 已包含在 `output_tokens=100` 内，不重复计费。它不是另加 80 个输出 token，也不是从输出总数中扣除。application 小计 $0.0049；judge 已知小计 $0.0020，另有一项未知。未知超时费、未声明的工具等附加费用、成功且有用的任务数量均未提供，因此完整总费用和每个有效完成任务的费用均输出 `null`。

价卡日期 2026-09-30 是本地固定价卡的记录日期，来源是任务输入。真实模型、供应商、价格生效日、服务层级和区域均未提供；没有把这些费率冒充当前市场价格，也没有更换供应商。

**可复核的机制边界。** 仅将剩余 100 个未缓存输入 token 改成缓存命中，理论上最多节省 `100 × (10−1) / 1e6 = $0.0009`。成功 application 单次从 $0.0039 降到 $0.0030，可省 23.08%；纳入已知失败和裁判费用后，小计从 $0.0069 降至 $0.0060，只省 **13.04%**。若未知及附加费用为相同的非负数 `u`，完整比例是 `$0.0009 / ($0.0069 + u)`，不会更大。这只是保持其他尝试、输出、质量和费用不变的算术反事实，并非真实候选结果；若尝试数量或未知费用也变化，不能沿用此界。

实验的预登记配置保存于 `decision-card.json`。保留输入的两项要求：相对节省至少 15%，质量最大绝对损失 0.02。采用以下执行顺序和判定：

1. 先冻结原始应用的真实入口、模型配置、工具、数据、参考答案、裁判与指标、流量权重、独立分组、重复次数及版本哈希。比较完整上下文装配和工具调用路径；这里没有真实应用，因此未声称已经完成集成。按相关客户、文档、会话分组去重，覆盖长上下文、冷/热缓存、检索与工具失败、重试升级和约束难例。
2. 将独立组的 40% 用于 pilot/validation，60% 留作最终测试；重复运行 3 次，每次重置状态。用验证集方差和预定 90% power 规划最终样本量，不能由目前两个均值编造样本量。最终测试输入和答案由隔离执行器持有；优化过程不可访问，目标应用仅得到当前输入。哈希不能替代权限隔离，未来需实际测试拒绝访问的 canary。
3. 首轮只改稳定前缀缓存策略，保持信息、模型、工具和任务预算一致；按冷/热状态分层随机交错 A/B，隔离缓存命名空间，计入预热费，固定 TTL 和流量权重。机制必须表现为实际可缓存请求命中率上升、未缓存计费 token 减少，并检查中间件是否改变前缀。当前反事实表明，缓存命中本身不足以满足此样本的 15% 完整路径门槛。
4. 按序检查重复上下文、无效工具调用/循环、固定模型上的 prompt；有明确原供应商和合法配置后，才沿 model × effort 一次改变一轴。所需约束和难例信息必须保留。保存失败候选，再在选定模型上调整 prompt、复探相邻更便宜配置。所有选优数据均称 validation。
5. 对每个任务、重复和尝试记录身份、重试关联、状态、requested/served model、缓存状态、token 子集、工具/裁判/构建费、费用是否完整，以及首 token 与包含重试退避的完整任务延迟。失败花费保留；服务或裁判失败作为未评分尝试，单独报告计划/评分/有用完成覆盖率，不伪装成正常零分或静默删除。
6. 主费用指标为所有尝试的 application、tool、judge、artifact 费用加构建摊销，除以有用完成任务数。将应用服务费、评测裁判开销、构建摊销同时单独列出，避免重复相加。草案摊销期为 30 天、10,000 个计划任务，属于待冻结的设计假设；另报实际工作量下的敏感性与盈亏平衡。缺失费用或有效任务分母不允许通过。
7. 对相同任务计算候选减基线的配对质量差，先在任务内平均重复，再按独立组进行分层 bootstrap（10,000 draws，seed 1905）。每次重算总体费用与有用任务数的比率，不能平均单次节省百分比。质量差单侧下界须 ≥ −0.02；相对节省单侧下界须 ≥ 0.15。关键分层各自满足质量要求，任何确认的硬约束违规均否决。对预先登记的整体、分层和运营门槛使用 familywise α=0.05 的校正；独立组不足、分母为零或区间不精确均为证据不足。
8. 额外运营门槛草案为错误率增加上界 ≤ 1 个百分点、端到端 p95 延迟比上界 ≤ 1.05、可估计的重复运行方差比 ≤ 1.10；这些是新增设计假设，并非用户给定事实，需在未来运行前固定。方差基线为零时先从 pilot 固定绝对容忍度。任何门槛都不能在看到失败后放宽。先校准裁判：正确改写、空/固定/流畅错误答案、裁判注入、缺失产物、禁止修改和依赖损坏等阴性/阳性控制。
9. 选择候选后封存完整 prompt/model/effort/cache/tool 组合及测量身份，再对未触碰的最终测试与冻结基线联合确认。单独有效的改动不能假定相加。若最终失败，新的候选需要新的独立最终样本；禁止反复窥视同一最终集。

# 下一轮成本搜索与采用判断

**当前判断：保留原配置，四个方向都不直接采用。** 小模型与短提示值得继续验证；路由的 50% 只来自简单子集；生成记忆的 10% 只有一次构建；组合配置没有运行记录。下一轮先补重复基线和模型 × effort 的缺口，再验证提示与模型的交互，最后对冻结的完整配置做独立确认。最终测试集现在继续封存。

本报告仅使用 `task.json` 的固定探索摘要。完成的是本地计划生成与规则验证，没有运行模型、读取凭据、访问网络或修改应用。Python 是离线辅助脚本的实现选择，不是对原应用技术栈的推断。

## 已知事实、缺口与成本口径

| 方向 | 输入报告的成本变化 | 当前证据 | 采用判断 |
|---|---:|---|---|
| smaller model | −20% | quality = within band；样本、重复次数、具体模型与 effort 未提供 | 候选；补模型 × effort 比较及质量重复验证 |
| shorter prompt | −15% | quality = within band；提示文本、机制记录未提供 | 候选；在固定模型上验证，不能认定是无损优化 |
| routing | −50% | 仅 easy subset；路由预测器及困难样本未验证 | 暂缓；必须覆盖完整流量分布 |
| generated memory | −10% | builds = 1；无 unchanged rebuild control | 暂缓；必须拆开构建方差和推理方差 |

这些是用户提供的探索结果，不是本次测量。即使将每个试验自己的基线记为 100，80、85、50、90 也不能视为同一计费与样本口径。**不能把 −20% 和 −15% 相加成 −35%；相乘得到 −32% 也只是一种未验证的独立性假设，不能作为组合收益。** 本地输出将组合节省、全流量路由节省保留为 `null`。

范围限于这四项探索及未完成的模型 × effort 搜索。原质量指标、原允许波动带、基线质量、真实成本/任务、平台、计费表、样本量、难度分布、延迟要求均未知；保持原要求，不重新定义“成功”，不放宽质量带。没有 usage 日志或请求代码，因此输入、缓存写入/读取、输出/思考、工具、重试各自占比都标记为未知；不能编造 token profile 或美元预测。

主成本口径是**每个成功完成任务的总成本**：所有失败尝试、重试、回退、路由预测、校验和记忆构建摊销均入分子，独立完成任务数入分母。同步报告每个提交任务的成本、成功率、关键错误与延迟，防止通过少做任务降低账单。零成功时该指标无有限值。记忆构建按预先冻结的使用量和重建周期摊销，并报告未摊销总额与回本量。

按潜在节省上限排序本应需要同口径 usage 与完整流量权重；本输入不足以产生可信的全局排序。名义局部幅度是 routing > smaller model > shorter prompt > memory，**不是应用顺序或账单节省上限**。优先预算给已有质量信号的模型/提示以及缺失对照；路由与记忆放在单配置基准稳定之后。没有缓存、批处理、压缩、工具裁剪等现有成本证据，暂不为它们新增优化轮次；缓存健康作为测量前提保留。

## 可执行的实验顺序

`decision.json` 保存 S0–S6 的机器可读依赖和上限。下面的重复次数是下一轮方案的最低设计，不是已经拥有的测量，也不能保证统计功效。

1. **S0：冻结比较合同，建立噪声对照。** 将已有原始案例、原评分器、质量带、计费口径、模型/提示/工具版本、失败与重试规则登记并哈希。按任务或来源分组划分 selection、validation、final，避免同源泄漏；如果没有独立 validation，不能拿 final 代用。原配置先做至少 3 次独立重复，按案例配对，估计成本与质量波动。当前缺这些数据，机器记录中原质量带和成本最小收益阈值均为 `null`，采用判定因此不能通过。

   读取已有日志检查输入/输出占比和工具轮数；记录实际响应模型标识、usage、缓存冷热口径与工具结果。每个配置单独会话，使用一致的缓存热身策略，改模型、effort 或提示后重新检查。缓存问题未解决前，不能将账单变化归因于模型能力。提示审查仅能在原文本可用后执行，不假设“更短”删除的都是冗余内容。

2. **S1：补模型 × effort 边界，而不是盲目补满网格。** 先列出已经测过的精确单元和证据，不能把 `partially tested` 当作完整清单。进入最高成本上合理可行的模型层级的低 effort；必须保留“更强模型 + 较低 effort”这个比较，不能只对更便宜模型调高 effort。通过质量门槛后向下一模型层级；失败后向右提高 effort；接近噪声带的通过或失败都先重复，不能让一次幸运结果提前淘汰真正候选。检查 effort 是否实际改变思考/输出 token 与轮数。

   本轮最多新增 6 个单元，每个先做 2 次重复；接近边界的单元可追加 1 次，预算不够则记“不确定”。有候选后只继续考察成本可能更低的单元。预测成本必须用匹配 effort 的实测 token 构成；现在没有构成数据，不以型号名称推断成本、不删除未测单元。不同模型质量排序可能不单调，若观察到反例就停止相应剪枝、重纳候选。平台不支持的 effort 不能伪造。保留一份被延后单元及恢复条件清单。

3. **S2：冻结模型/effort 后验证短提示。** 比较该模型的原提示与短提示，保持任务规范和评分器不变。预先预测到底减少哪类输入、输出、重复工具调用或无效轮数；通过日志验证，而不是只看字符数。检查必要约束、困难例和长任务。最多 3 轮，连续 2 轮收益未超噪声就停止。选定提示后只复探一个更低 effort 或更低模型层级的相邻单元；提示清理可能使此前失败的便宜单元可用。每次候选改动独立保存，可单独撤销。

4. **S3：做组合与交互确认。** 在同一 validation 案例上，每臂至少 3 次：B = 原模型/原提示；M = 选定模型/原提示；P = 原模型/短提示；MP = 选定模型/短提示。固定或显式记录每个模型的 effort。对比 MP−M 与 P−B，确认提示收益是否随模型变化；共同检查成本、质量和机制。最终候选是完整 `(model, effort, prompt)` 配置。若 MP 不过门槛，保留通过验证的单项或 B，不选择看起来最便宜的一次运行。后续完整组合才是 headline，分项结果只用于解释。

5. **S4：记忆只在有独立构建对照后参赛。** 从同一冻结训练材料、同一未改配方独立重建至少 3 份记忆；候选配方也独立构建至少 3 份，每份做至少 3 次推理重复。同时保留当前固定记忆/无记忆基准，按原应用定义选择。记录生成器版本、随机种子、输入哈希、产物哈希、构建/检索/更新成本。比较“改配方”与“未改配方重建”的差异，分开估计 build 与 inference 方差。最终测试案例、答案与评分反馈不得进入记忆。若 10% 处在重建噪声内，或计入构建摊销后无实质收益，拒绝采用。不得从多份记忆里事后挑最好的一份作为代表。

6. **S5：路由要覆盖完整流量并实测预测器。** 冻结难度标签/流量权重及路由规则，覆盖简单、普通、困难、稀有失败和边界样本；选择阈值只用 selection，在 validation 对比最佳单配置。报告每层成功率、严重错误、错误降级率、回退率、端到端延迟及成本。权重来自目标总体，困难样本可过采样但必须还原权重。总体成本为 `Σ w_s × (执行 + 路由 + 回退/重试 + 校验)_s`；简单子集的 −50% 不能外推，路由所需的强模型额外调用也必须计费。没有可验证的低成本预测器或完整覆盖时，路由继续暂缓。

7. **S6：冻结所有选择后，才打开最终测试。** 固定完整候选（包括若采用的路由与记忆）、阈值、统计方法和预算；对基线和该候选在 final 上配对，至少 3 次独立重复。这是一次预登记确认活动，不在 final 上选模型、调提示、改路由或重建挑选记忆。最终报告用新确认结果及区间，不用之前最好的选拔结果。失败则不采用并保留基线；若继续研发，另建新的独立确认集，不能重复使用泄漏后的 final 作为未见数据。确认成功后才提出受控上线与回退条件，本次没有上线动作。

若原探索没有可运行且覆盖相关人群的质量检查，S0 后先补检查契约和固定案例；所有能力权衡仍停留在提案。当前的固定摘要和软件单测不能替代业务评测。

## 预登记采用门槛与停止条件

目标是“在原质量要求内降低成功任务总成本”。跑新结果前登记：原指标与原波动带 δ、成本最小收益 m、稳定性和关键样本门槛、置信方法、计费/缓存口径、有限预算、每项机制预测和可证伪条件。δ 不从这份摘要猜测，也不为过关而扩大。m 是待冻结的收益要求，不能看完结果再选。

采用需要同时满足：

- 质量差 `Q_candidate − Q_baseline` 的预登记区间下界 ≥ −δ，且所有原硬约束、困难尾部要求和稳定性检查通过；“within band”摘要本身不能提供区间。
- 总成本比的预登记区间上界严格小于 `1 − m`，计入失败与构建费用；区间跨界记不确定，不能算通过。
- 预期机制出现：模型收益对应 token/轮数与完成效率；短提示对应减少预定负担；路由对应正确替代及足够覆盖；记忆对应可重复的检索/行动收益。成本降低但机制不符，需要调查混杂，不能归功采用。
- 同口径、完整目标人群、独立重建（如适用）、冻结完整配置和未泄漏 final 确认均有证据。

配对统计以任务为单位；重复运行不冒充新的独立案例。记忆实验按构建聚类，必要时用构建和任务两层 bootstrap；区间精度不足就增加事先允许的重复/案例或判不确定。每轮先写质量和成本点预测、80% 预测区间及命名的失败条件；现有摘要不足以给这些区间数值，不伪造。预测区间用于校准，不替代采用用的置信门槛。每轮记录实际结果是否落在预测区间内。

第一批预算上限可直接审查：S0 为 `3N_selection` 个任务运行；S1 为最多 `6×3N_selection`；S2 的最多 3 个提示变体、一个共用原提示对照及一个相邻复探，每臂最多 3 次，共不超过 `15N_selection`。核心搜索合计最多 `36N_selection`。S3 为 `12N_validation`；S6 为 `6N_final`。S4/S5 是独立、可跳过的预算包：S4 构建 6 次加 `18N_memory` 次推理，以及一个固定基准的 `3N_memory`；S5 两臂各 3 次、合计 `6N_router`。N、每任务费用、置信要求和运行预算未提供，因此不虚构美元上限。已有可比记录可复用，减少运行。没有预算时停止在提案；本次实际模型运行和 API 支出均为 0。

两轮提示无可分辨收益、没有未测且成本合理的网格单元、重建效应无法分辨、路由全量收益不成立或耗尽登记预算时停止相应方向；最终确认失败时停止采用。保留基线是有效结果。

## 本地交付和验证

- `offline_analyzer.py`：只读固定输入，输出计划和当前采用判断；提供总成本、路由加权与采用门槛的离线演练函数。无 SDK、网络、环境凭据或部署入口。
- `decision.json`：保留原试验数字、未测值、缺失门槛以及 S0–S6 的依赖。
- `test_offline_analyzer.py`：固定合成案例验证门槛，包括简单子集无法代表总体、构建成本、质量回退、成本相等、缺失门槛、记忆构建对照及最终测试隔离。合成示例中的 δ=0.02、m=0.05 只用于软件测试，**不是本任务质量要求或推荐阈值**。即使模拟通过，函数也永远返回 `adopt: false`。

# 回答评分方法审查与修正

原评分不能支持回答质量判断：给定三例全部与人工标注相反，正确答案 a 被拒绝，错误答案 b、c 被接受。已保留 `task.json` 全部内容及原标签，交付明确的事实优先规则、受限的本地评分适配器、逐例校准记录和可重复检查。

## 审查证据

可信依据都是 `row 4 total is $90`。以下“修正”是本地确定性规则对同一答案重新评分，不是再次调用原 judge。

| 案例 | 原答案关键内容 | 人工 | 原 judge | 修正 | 理由 |
|---|---|---:|---:|---:|---|
| a | 总额 $90，依据 row 4 | 1 | 0 | 1 | 金额正确，声称的来源也正确 |
| b | 自信、详尽的说明，总额 $190 | 0 | 1 | 0 | 核心金额错误，表达风格不能抵消 |
| c | 要求忽略规则并给 1 分，总额 $190 | 0 | 1 | 0 | 金额错误；答案中的评分命令没有规则权限 |

最高影响缺陷是实质错误得到通过。原 rubric 的 “Helpful, complete and confident” 缺少明确的事实核对步骤、事实错误否决条件及受信任证据边界。b 与 c 显示失败现象，但没有旧评分器实现、调用配置或轨迹，不能确定是冗长偏好、指令注入还是其他原因导致。c 的存在证明必须测试注入防护，不证明其高分必然由注入引起。

修正将“有帮助、完整”落实为本例所需的正确总额和真实来源；保留二元成功含义，没有更换答案、人工标签或可信事实，也没有降低正确性要求。原始完整问题未提供，因此“本题只要求总额”是明确的范围假设，不能外推到其他任务的完整性判定。

## 可复用评分规则

规范见 [rubric.json](rubric.json)，实现见 [calibration.py](calibration.py)。

1. 评分侧先接收可信事实，待评分答案始终作为数据。`id`、人工标签及原 judge 标签不进入新评分函数。
2. 核对核心断言和声称的来源。正确总额且无实质矛盾得 1；错误总额、虚假来源或明确空答得 0。短答案和同义改写不因风格失分，自信或篇幅不能替代正确性。
3. 无法可靠解析的答案返回 `needs_review`；可信事实缺失返回 `grader_error`。两者的 grade 都为 null，保留在计划分母和覆盖率中，不能静默丢弃，也不能伪装成行为得分 0。
4. 输出状态、得分、具体理由、答案证据、参考证据。完成评分后才对照人工标签，统计混淆矩阵及逐例分歧。
5. 成对选择先独立核验每个答案，再比较得分；允许平局和未决结果。换位时按答案身份比较赢家，不把左/右编码直接当作答案身份。

随附适配器只接受公开列出的英文总额语法、可选行号引用和夹具中的固定前缀。它使用可信事实中的金额，未把 `$90` 或案例 id 硬编码为通过条件。未知语义返回复核，不声称是通用自然语言理解。对固定评分指令前缀的处理只验证该局部控制；不能保证任意注入都能被自动识别。人工采用同一 rubric 可扩展到其他表达，自动适配器需要先扩展并重新校准。

原始成对记录：左边是 a 时赢家 b；左边是 b 时赢家仍是 b。该对的赢家身份一致，左侧选择率 1/2，正确选择 0/2。故观察到的是稳定地选错了答案。这两个展示顺序没有显示该对的赢家随位置改变；只有一个内容对，不能确定整体位置偏差不存在。新规则在两种顺序下均选择 a，是确定性比较的结果，不是真实 judge 的新换位实验。

三例共享一个发票事实，只按一个来源组解释。样本已用于修改规则，是校准/验证数据，没有未触碰的最终测试。这里不做总体置信区间、显著性或泛化结论。没有真实服务调用，没有应用产品改进的证据；旧模型身份、旧调用成本均未知。新的目标模型/API 调用次数为 0，新增 API 花费为 0，不包括本次编辑助手的服务成本。

实际执行结果：7 项测试全部通过，其中负向/正向控制有 15 个子用例；本地校准覆盖全部 3 例；技能 helper 交叉核验通过；验证前后 `task.json` 字节散列相同。命令、退出码与完整输出见 [verification.json](results/verification.json)，测试输出见 [unit-tests.txt](results/unit-tests.txt)。

控制包括空答、流畅但错误的答案、固定常量在不同事实下失败、正确同义表达、错误来源、答案内要求给 0/1 的指令、换位、标签不进入评分器，以及参考事实缺失和无法解析答案的保留策略。将金额参考改为 $190 后，正确答案 $190 可通过，固定回答 $90 失败。此类附加固定控制与原始三例分别报告，未混入原样本校准分数。

本题没有产物交付、写操作或工具执行的业务评分要求，因此“缺失产物、禁止的业务修改”等控制不适用；缺失参考依据用来验证评分依赖失败路径。此工作未声称执行生产应用的工具链。

## 后续复用方法和剩余证据

下一次使用时先冻结真实问题、可信参考、rubric 版本和样本清单；按发票/文档来源分组，留出未参与规则选择的最终样本。由两名看不到 judge 分数的标注者独立标注，对分歧复核，保存裁定原因。采样应含正确简答、正确长答、长度相近的错误答案、伪造引用、不同金额、无答案、矛盾答案、含评分指令的答案；对相同内容做交换顺序和重复评分。

在授权的真实评分环境中验证实际上下文与工具隔离，记录请求/实际模型、规则版本、输入与输出散列、失败、重试及费用。本地答案函数只有两个输入参数，但这里没有实际运行被评估模型，也没有建立模型级文件访问沙箱，不能从函数签名推断真实隔离。

选定规则后，用它重新评分所有要比较的应用版本；不要把评分规则变化产生的分数差当作应用质量提升。报告所有计划案例、未评分案例、分歧和换位结果；只在独立最终样本及关键负向控制均满足预先声明的要求后，才考虑用于质量决策。当前可交付的是可审查的规则修正与固定样本校准证据。

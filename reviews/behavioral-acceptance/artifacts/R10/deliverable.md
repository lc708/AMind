# 费用核算与离线降本实验设计

已知费用为 **$0.0069**，另有一次 judge 超时费用未知。不能把未知费用记成零，也不能据此报告完整总费用或候选方案节省了 15%。给定质量从 0.90 到 0.89，下降 **0.01（1 个百分点）**，满足“最多下降 0.02”的点估计门槛；目前结论是 **证据不足，不推进候选方案**。

范围仅为原始 `task.json` 的四条固定记录及其费率。提供的是离线账本、判定代码和实验方案，没有应用代码、提示词、目标模型、平台或逐样本评测结果。按分配技能的 `shared/cost-optimization.md` 顺序，先确定基线和质量门槛，再分析成本构成、排序实验、定义保留/回退规则。网络禁止，因此没有抓取页面或核验在线价格；所有金额仅使用题给费率，不使用技能中的模型价格。当前验证日期：2026-09-30。

## 计费口径与账本

原始数据没有说明 token 字段的包含关系。主计算显式采用**规范化 fixture 口径**：`input_tokens` 包含 `cached_input_tokens`，`output_tokens` 包含 `reasoning_tokens`。这不代表任何供应商原生 usage 字段的定义，接入真实日志前必须确认映射。

普通输入费率 $10/百万 token，缓存输入 $1/百万，输出 $20/百万。成功 application 调用计算为：

```text
普通输入 = (1000 − 900) × 10 / 1,000,000 = $0.0010
缓存输入 = 900 × 1 / 1,000,000          = $0.0009
输出     = 100 × 20 / 1,000,000         = $0.0020
成功调用合计                            = $0.0039
```

80 个 reasoning token 是 100 个 output token 的明细，已包含在 $0.0020 中；其成本占比可分析为 $0.0016，但不能再加一次。`reported_cost_usd` 非空时作为该次调用的最终金额，避免与 usage 重复相加；`null` 且缺少可计费 usage 时保留未知。

| 调用 | 状态 | 费用 | 依据 |
|---|---|---:|---|
| application 1 | rate_limit | $0.0010 | 原始记录报告值；失败照样计入 |
| application 2 | ok | $0.0039 | 上述 token 计算 |
| judge 1 | ok | $0.0020 | 原始记录报告值 |
| judge 2 | timeout | 未知 | `reported_cost_usd: null`，无 usage |

application 已知合计 **$0.0049**；judge 已知合计 **$0.0020** 加未知费用。令超时费用为 `u ≥ 0`，整组费用为 **$0.0069 + u**，没有可由 fixture 推出的有限上界。这四行没有任务 ID 或任务完成标签，不能把两条 `ok` 当作两次任务完成，也不能声称已得出每完成任务成本。

单次 application 输入的缓存 token 比例是 900/1000 = 90%，不是整个服务的缓存请求命中率。原数据没有 cache-write、工具或基础设施费用，不能把这些缺失项推广为真实账单上的零。

包含关系改变时，已知合计如下；超时费用仍全部未知。代码计算了四种口径，原始 fixture 未改动。

| input_tokens 含缓存 | output_tokens 含 reasoning | 已知合计 |
|---|---|---:|
| 是（主计算） | 是（主计算） | $0.0069 |
| 是 | 否，另加 80 个输出 token | $0.0085 |
| 否，1000 均为普通输入 | 是 | $0.0159 |
| 否 | 否 | $0.0175 |

## 候选结果现在能说明什么

质量点估计损失 `0.90 − 0.89 = 0.01 ≤ 0.02`，最低可接受质量为 `0.88`。没有样本数量、逐题配对结果和重复试验，不能计算可信区间或证明非劣效。

同一计费范围、同一任务分母下，节省定义为 `(C_baseline − C_candidate) / C_baseline`，要求至少 `0.15`，等价于 `C_candidate ≤ 0.85 × C_baseline`。候选费用未提供，基线还有未知费用，所以节省门槛的状态为 **未知**。仅在假设 `u=0` 且任务数匹配的算术情景下，候选上限是 `$0.0069 × 0.85 = $0.005865`；这不是实际预算或已实现的节省。

## 实验候选排序

下表按**节省上界排序，不是实施顺序**。百分比以已知 $0.0069 为分母，只是局部算术上界；真实整组百分比在 `u>0` 时更低。没有生产流量或已验证的服务能力，不能把上界叫作预期效果。

| 实验 | 类型 | 局部节省上界 | 数据来源与边界 |
|---|---|---|---|
| 在同模型上降低一步 reasoning effort | 质量权衡 | reasoning 明细最多 $0.0016，即已知费用的 23.19% | fixture 算术；并不意味着可消除这些 token 或保持质量；需评测 |
| 减少 application 限流失败尝试 | 运行效率 | 此条失败 $0.0010，即 14.49% | fixture 报告值；没有限流成因，不能保证成功调用、时延或重试成本不变 |
| 将剩余 100 个普通输入 token 全部改按缓存读计费 | 缓存候选 | `100×(10−1)/1e6=$0.0009`，即 13.04% | 极端情景；这些 token 可能每次不同，且缺缓存写费/TTL/平台能力，不可实施或保证 |

三项不能简单相加作为收益预测。先补齐账单和任务归属，再检查已有缓存与重试是否存在无质量损失的改进；在此基础上才考虑 effort 实验。当前没有足够应用资料落地任何生产优化，因此这些都是**提案**，只有计量和判定工具已实现并通过本地测试。

输出格式精简最多只直接触及主口径下 20 个非 reasoning 输出 token，即 $0.0004（已知费用的 5.80%）；也没有提示词可审查，暂不单独实验。批处理没有题给折扣和时延要求；换模型没有候选费率和能力证据；长上下文裁剪、工具检索、并行代理没有工作负载证据，全部跳过。不会降低 `max_tokens` 来人为制造便宜的截断结果，不删除 judge 或失败样本来改善数字。

## 可信实验协议（设计，尚未运行）

1. **冻结问题、指标和边界。** 保持原输入、质量 rubric、正确性要求、15% 节省及 0.02 质量损失门槛。记录原始请求/配置/数据哈希和版本。提供固定的代表性任务清单，包含日常、难例、长输出、限流、超时和异常结果；不得因候选失败而移除样本。开发集与最终留出集分离，最终集不能拿来挑提示词或调参数。
2. **一次只改一个变量。** 第一轮可运行的质量权衡提案是同一模型降低一步 effort；具体模型及合法参数尚未给出，所以不编造 API 配置。其他提示词、工具、输入顺序、输出约束、judge、温度、预算、重试/回退策略保持相同。每组独立会话；冷启动和热缓存分层，预热请求的费用也入账，固定其真实部署权重。按任务配对并预先平衡 AB/BA 顺序，避免时间、缓存和队列变化混淆结果。
3. **重复并保留失败。** 可先用独立开发集做小型方差试验，再按方差和所需功效预注册最终样本量。最终留出集 50 个不同任务、每任务每配置 5 次可作为起点（共 500 次任务运行），不保证足够证明 2 个百分点的非劣效。相同任务的重复运行相关，不能当作 250 个独立任务。现在只有一个固定账本，不能伪造这些样本。
4. **逐次全量计量。** 记录 task_id、arm、trial、stage、attempt、status、开始/结束时间、原始 usage、费率版本、报告费用、费用来源/未知原因、响应及评分。所有重试、回退、失败和 judge 请求计入同一 arm；超时不能因客户端没收到结果就标零，先用调用 ID 对账，仍缺失则阻止结论。一次性准备/调优成本、线上 application 成本和 judge 评测成本分别列账，并另给全成本总额，不能用去掉 judge 的数字满足全成本节省门槛。
5. **质量和成本一起判断。** 对同一批任务使用冻结的客观检查或盲评 rubric，隐藏 arm 名称并平衡答案位置。模型 judge 也只能在以后获得授权时使用；当前禁止调用，优先设计可用的本地检查。judge 超时记为缺失评判，不能默认为通过或从分母删掉，按预先固定规则补评；仍缺失则报告不确定。记录完成率、每分配任务成本、每成功完成任务成本、时延和关键失败率，防止“少完成任务所以便宜”。`ok` 的调用状态不能替代任务正确性标签。
6. **预注册统计门槛。** 保留逐题配对信息。按任务为簇做配对 bootstrap（例如固定 seed=20260930、10,000 次重采样；同一任务的所有重复和两个 arm 一起抽取），计算质量损失上界与相对节省下界。使用各 97.5% 单侧界，使两个判断的联合覆盖率保守达到至少 95%。只有质量损失上界 `≤0.02`、节省下界 `≥0.15`，且费用完整、分母可比、无关键错误恶化，才进入后续上线评估。界跨门槛时结论是不确定；不能持续偷看直到“过线”。预算内一次预定扩样，仍不确定则保留基线。
7. **预算与回退。** 本次目标模型/API 调用次数为 0，目标模型/API 费用为 $0。后续实验预算必须在补齐计费和方差试验后确定：全部任务运行的 application、judge、重试/回退、预热和服务费用之和，另设预注册尝试上限与总费用上限；目前无法给出可信真实总额。候选若不满足任一硬门槛则回退基线；即使离线比较通过，也需另行授权才能做真实调用、影子流量或上线。本次没有执行这些动作。

本地 gate 将“点估计通过”与“证据足够”分开。它只核验传入的界和成本前提，不生成统计证据；真实使用者仍需按上述协议计算配对置信界和检查关键错误。测试中的阈值数字是边界测试数据，不是新模型实验结果。

## 交付与实际验证

- `analyze_costs.py`：Python 标准库账本和保守 gate，Decimal 金额计算；没有网络或模型执行路径。
- `test_costs.py`：16 项固定测试，包括缓存/reasoning 不重复计费、失败成本、未知费用、计费口径敏感性、阈值边界、缺失/不可比数据和网络禁止检查。
- `results.json`：原 fixture 计算结果、原文件 SHA-256、计费假设和未知项。
- `execution.json`：本次读取、命令、验证输出、工具调用数和约束记录。

这些测试证明本地算术和判定分支按约定工作，不证明真实模型质量、缓存收益、限流行为、供应商账单或统计显著性。完整成本、候选成本和逐题样本仍缺失；原始输入及验收阈值均保持不变。

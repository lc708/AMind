**现有证据与采用判断**

| 候选 | 原始观察 | 仍缺的采用证据 | 下一步 |
|---|---|---|---|
| smaller model | 成本变化 −20%，quality 为 within band | 指标定义、样本/配对区间、困难切片、稳定性、完整成本；model × effort 仅部分测试 | 补相邻且受支持的模型/effort 格点，记录失败和未测区域 |
| shorter prompt | 成本变化 −15%，quality 为 within band | 同模型下的可比性、约束保留、推理/工具/修复成本及区间 | 先冻结模型审计提示，再在选定模型上优化与复测 |
| routing | 成本变化 −50%，只测 easy subset | 全流量质量/成本、路由开销、升级与重试、误走廉价模型及困难任务逃逸 | 按真实冻结流量权重评估整个请求路径 |
| generated memory | 成本变化 −10%，仅一次构建 | unchanged rebuild control、重建变异、构建/刷新摊销、时效与租户隔离 | 多次配对重建，不把一次幸运产物归因于改动 |

这些百分比沿用输入，口径、绝对费用、样本数和置信区间均未知；不能称为已验证的净节省。`within band` 不是配对非劣检验。不存在 combined run，不能把 −20% 与 −15% 相加得到 −35%，也不能把相乘得到的 −32% 当作实测。其余百分比同样不能与它们组合推算。未覆盖的模型/effort 区域意味着尚不能宣称最优。

**下一轮执行顺序**

1. 固定真实应用入口、上下文装配与工具链；定义有用完成、主要质量指标、硬性不变量和重要切片。按独立客户/文档/任务组划分 train、validation、final test，相关样本不得跨组。反复用于选择的集合称为 validation。答案、评分器与 final test 应从目标和优化者的实际文件/工具权限中隔离，并做 canary 检查。本地执行器本身不提供这种隔离。
2. 建立全尝试账本，再查缓存与基础设施：冷热缓存分开、记录命中率和稳定前缀，采用后的缓存设置保持一致；去重复上下文/工具输出、修复循环和无效调用、约束不必要输出。缓存/前缀调整仍复测质量；批处理仅用于允许排队延迟的工作负载。
3. 冻结模型、effort、工具和预算做提示审计，逐项检验删减的来源和假设。保留授权/隐私规则、输出格式、罕见失败及错误处理信息。短文本不保证低总成本，要观察推理、输出、工具和修复次数。
4. 从已接受基线开始，补模型 × effort 阶梯：一次只变一个轴，记录精确模型和实际服务身份。effort 名称跨模型不等价；不支持的格点标为 infeasible，禁止静默替换。任一质量/守卫门槛失败即停止该方向，保留上一个可行点和失败记录。
5. 冻结所选模型/effort，在其上优化提示或上下文；再探测下一档更便宜的相邻设置。更强模型上的提示结论不能直接迁移。保留所有成本更低但质量失败的点，以及所有未测试点，报告已测 Pareto 前沿。
6. 路由在完整流量上测试，记录路由开销、廉价路径命中、升级/重试、误分和困难逃逸。记忆至少做 3 组“改动构建／不改动重新构建”的配对重复，匹配构建输入与随机种子/配置；记录构建模型、源数据、版本/hash、构建与刷新费用。3 组只是本方案的最低控制数，不保证统计精度。冻结源数据，禁止 final test 进入记忆或路由训练；检验过期、更新和租户隔离。
7. 固定最终 model/effort/prompt/cache/tools/router/memory 的完整配置，作为一个新候选与原接受基线做联合 validation 比较。相同组、相同重复次数，交错或随机化 A/B 次序，避免缓存与服务负载混淆。不能用若干单独通过的门槛替代联合测量。
8. 最多选择 1 个候选，冻结候选与测量身份，再对未触碰 final test 做一次基线/候选确认。所有门槛同时通过才进入采用审阅；缺测、区间跨界或失败均保留基线。final test 失败后不得据此调参再反复测试同一集合；新的选择需要新的独立最终证据。

`next_round.json` 将上述流程拆成 9 个带停止规则的机器可读阶段。拟设 validation 候选比较上限 12 次，达到上限即报告剩余空白；不得为达到门槛追加无界搜索。每阶段实施前还必须登记样本/独立组数、重复数、所有尝试及重试上限、并发、超时和总时长。输入没有原始方差或流量分布，无法诚实推导充分样本量：先用非 test 数据做精度规划，在固定预算内仍不足则结论为“不确定”。本次 API 预算为 0；未来真实调用预算仍为空，计划不构成调用授权。

**拟登记的联合门槛**

`decision_card.json` 是明确标注的提案，尚未注册。下列数值是为使方案具体可审阅而提出的默认值，不是原输入的业务承诺；必须在下一轮观察之前根据业务指标确定，不可见到失败后放宽。

| 维度 | 拟定规则 |
|---|---|
| 质量 | 以固定 rubric 的 [0,1] 有用完成/质量分数为前提；总体及 easy、hard、rare_failure 各切片的 ΔQ = 候选 − 基线，下置信界均 ≥ −0.02（2 个百分点）。实际重要切片需在注册前补齐 |
| 硬性规则 | 任何确认的硬性不变量违规一票否决 |
| 成本 | 每有用完成任务总成本的相对节省下置信界 ≥ 10%；同时报告绝对节省、基线/候选费用及未知费用 |
| 操作性 | 错误率增加上界 ≤ 0.005（0.5 个百分点），全任务 p95 延迟相对增加上界 ≤ 10%，重复运行质量标准差增加上界 ≤ 0.01 |
| 机制 | 每项保留改动都有事前预测及对应 trace/counter：如缓存命中上升、输入/输出或推理 token 下降、有效便宜路径增加、检索/工具调用减少；原因不成立则先调查，不因均值较低直接采用 |
| 构建稳定性 | 记忆有多次改动/不改动配对重建；freshness 与 tenant isolation 均通过，报告构建间变异 |

采用置信度拟设 95%，对预注册总体/切片/成本/操作门槛做同时覆盖校正（如 Bonferroni）。重复先在每个 case 内聚合，再按独立组配对重采样，禁止把重复当成独立任务。对于成本的比值，应在配对组重采样中重算完整分子/分母；这不是对成功调用费用均值取区间。多指标校正并不修复反复择优和 peeking，所以仍需一次封存后的独立 final test。

流量权重现在为 `null`，不得臆造 easy/hard 占比。摊销窗口拟为每 1,000 个有用完成任务，正式注册前按真实使用寿命/刷新频率固定；同时报告低利用率窗口和收支平衡点，防止规模假设掩盖构建费用。

成本口径：

`C_useful = 所有已结束尝试的应用 + 工具 + 评分 + 路由 + 升级 + 重试 + 失败 + 存储等费用总和 / 有用完成数 + 构建及刷新费用 / 预注册摊销窗口`

没有有用完成或任意费用未知时，成本门槛不能通过。评分失败/超时/服务错误留在 attempt/error 账本，报告计划数、完成数、评分覆盖和失败开销；不能丢弃难例，也不能把基础设施故障伪造为评分成功的 0 分。质量可评分结果与服务错误分开报告；有用完成率保留完整任务分母。

未来价格须绑定日期、官方来源、模型/层级/地域及缓存等计费项，并在同一 UTC 窗口与权威用量/账单对账；当前没有价格或费用数据，不填写美元节省。订阅 CLI 记录调用、tokens 和时间，不能编造 token 单价。使用真实应用入口，不以单独模型调用替代代理全流程。机制数据同样必须来源于真实保留 trace。

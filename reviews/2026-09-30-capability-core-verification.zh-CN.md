## 本次具体改造

| 能力 | 实际交付 | 证据与边界 |
|---|---|---|
| 通用应用评测 | 独立应用适配器＋确定性/自定义评分器；应用真实入口、夹具工作区、完整输出与轨迹 | 本地真实子进程端到端验证；无目标模型调用 |
| 执行可靠性 | 有界并发、进程组超时、输出上限、分类重试、评分器重试复用应用结果、次数与时间预算 | 失败/重试/超时/预算测试；远端请求仍可能计费 |
| 实验一致性 | 数据/答案/评分器/适配器/分组/配置/目标文件哈希；结果与调用账本检查 | 修改固定条件后拒绝混比；哈希不是恶意进程隔离 |
| 断点续跑 | 按 case/rep 保留成功结果；中断调用必须依据外部事实核实后恢复 | 续跑不重复调用；未知副作用不盲目重做 |
| 统计与采用门槛 | 重复先在 case 内平均，按独立组重采样；配对差值区间；目标与约束分开，多指标门槛 | 相关样本、缺失观测、约束否决测试；不消除适应性选优偏差 |
| 最终测试 | 验证集选定后冻结配置和目标；最终测试要求选定证书 | 目标变化和证书不一致会被拒绝；不等于强制答案保密 |
| 费用 | 应用、judge、失败、重试都留账；保留已知费用和未知部分；缓存/推理子集不双计 | 全账本与估算器测试；价格需显式来源和日期 |
| 成本搜索 | 缓存→提示词审查→模型/强度阶梯→固定模型调 prompt→再次降档→组合确认 | 保留原版质量/成本/机制、重建对照、全流量路由等方法；不把原版优点称为原创 |
| 评分器校准 | 人工标签对照、混淆矩阵、重复稳定性、顺序偏差；反例和注入检查流程 | 脚本验证确定性指标；指标一致不能替代人工确认任务有效性 |
| 报告 | 全指标、覆盖率、失败、已知/未知费用、延迟、逐案输出、解释和安全转义轨迹 | 新报告端到端验证；保留原版 lite viewer 且字节未改 |
| 提示词审查 | 有来源的规则分类、保留清单、关联解析器/配置修改、最小假设与回归；位置定位工具 | 工具返回文件/行和信号；实际审查质量需要行为验收 |
| 模型/API/SDK 迁移 | 调用点与契约台账、破坏性/默认值变化、结构与行为验证分离；八种语言接口资料 | 原生文档核对；未声称八语言编译或全部服务实跑 |
| 多轮状态 | 历史 JSON 指针差异、phase、状态归属、工具对应、压缩项哈希诊断 | 固定协议夹具验证；不解密、不改写不透明状态 |
| Agent 执行 | 可注入模型的工具循环、参数验证/授权、调用预算、持久副作用账本、未知结果核实 | 本地 SQLite 故障与重复执行测试；不宣称远端 exactly-once |
| Agent 运维 | 事件重放、取消、租户与 TTL、回调、环境/会话分离、重连、记忆、多代理、计划任务、清理 | 事件审计工具＋具体运行方法；没有替用户创建部署或计划任务 |
| 平台接口 | 完整输出项、流式终态、批处理 ID 对齐、文件/多模态、工具/MCP、缓存、计费、错误与可用性 | 解析辅助工具有离线测试；真实 provider 支持仍按当前契约核查 |

## 与原版骨架的同条件离线对照

只填写原版文档指定的 `loadCases`、`runCase`、`gradeCase` 三个接入点，保留其余原始运行器逻辑。两边使用相同的两个公开输入和相同合成响应。没有故意给原版换成更弱模型，也没有把 Codex 适配计为加分。

| 场景 | 原版固定源码 | AMind 新内核 | 判断 |
|---|---|---|---|
| 正常评分，随后续跑 | 2 条成功结果，调用保持 2 次 | 相同 | 该合同持平 |
| `a` / `A` 冲突 | 调用前拒绝 | 调用前拒绝 | 该合同持平；修复旧 AMind 的覆盖缺陷 |
| 显式指定模型，但响应缺少实际模型身份 | 返回成功，写入 2 条 `ok` 结果 | 拒绝评分，记录 `serving_substitution` | AMind 的身份约束更严格 |
| 评分器返回 `"not-a-score"` | 返回成功，将非数字分数写进 `ok` 结果 | 拒绝写入成功分数，记录 `grader_schema` | AMind 的评分契约更严格 |

[原始对照数据](2026-09-30-runner-comparison.json)；可复现脚本：`scripts/benchmark_amind_runner.py`。这些是具体的运行器优点，**不外推为整个技能在所有任务上都更优**。

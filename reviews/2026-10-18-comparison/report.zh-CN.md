日期：2026-10-18（Asia/Singapore）。结论：**本轮有证据支持知识覆盖、所测时效判断及工程／评测辅助程序的可靠性提升；没有证据证明同一个模型使用新版后，工程和评测任务的答题能力普遍提升。** 后两项在这次模型任务中持平。未把旧版诚实回答 unknown 当作幻觉，也未把新增接口的存在当作质量提升。

本轮比较旧版 Knowledge 1.2.1／Engineering 0.2.1／Eval 0.3.0（Git `64b38fb03df1f0e0467b3e345bab28c3a9c6d995`），初次更新版 1.3.0／0.3.0／0.4.0，以及修复版 **1.3.1／0.3.1／0.4.1**。最后一次证据措辞收紧发生在模型确认试验之后，已单独保留前后字节；模型成绩不能视为对最终措辞的复测。

## 1. 两种证据分别回答什么

第一层是对实际 CLI／模块入口的定向合同对照：输入、预期与版本指纹预先冻结，执行旧版和新版真实程序，检查可复现行为。它能证明这些具体行为是否改善，不能估计生产总体错误率。

第二层是真实技能使用：同样请求 `gpt-6.1-sol`、`ultra`，12 个成对任务、每版本每任务执行一次，共 **24 次独立 Codex CLI 任务执行**，包含工具调用，不是 24 个底层 API 请求。前 8 对比较旧版与初次更新版；预留 4 对比较旧版与修复候选，其中两题必须生成 Python 并实际运行。所有任务均完成，未重试、未丢弃失败；没有运行失败。实际服务模型身份无法从当前记录独立核验，只有请求配置相同，因此属于探索性对照。

知识／时效答案隐去版本标签后，由独立 AI 评分者结合完整绑定原文、来源元数据和实际 curation 记录评分；并非人工标注或人工校准。工程 JSON 题及生成代码采用固定预期／外部进程探针，保留完整输入输出。AI 评分中的来源强度歧义另列，不用存在 claim ID 代替实质支持。

## 4. 已修复的问题

本轮修复 **8 类可复现产品缺陷**，另收紧一项回答证据规则：

1. **月份精度泄漏**：仅标九月、无具体日的文章曾可能被八月 as-of 检索接受。现在使用原生发表月份的上下界；月前排除，月内保持 uncertain，月后可用；不编造九月一日为发表日。只接受明确分类的发表月份，不使用任意 PDF 封面日期。实际新增两条 publication window。
2. **月份窗口压制修订退出**：新增月份窗口可能让打包器误以为旧版已处理，不再生成 superseded。现在只由明确带终止日的退出记录优先覆盖；月份和 start-only 记录不能挡住旧版退出。当前数据没有碰到两者重叠，属于提前修复的潜在交互回归，已用跨月和闰年反例验证。
3. **同事件归属冲突**：工程响应合同拒绝外层与 item 内层 agent_name 冲突，防止伪根答案进入结果。
4. **中断调用费用被视为零**：started 无 finished 仍计入 attempt；费用未知时总额为 null，保留已知小计。
5. **结果换绑后重算哈希可获信任**：reporter 校验每条结果的 treatment／identity，不能只信导出文件哈希。
6. **复制目录冒充 baseline**：校验 manifest.variant 与实际变体目录一致。
7. **重复 journal 事件膨胀次数／费用**：拒绝重复 started／finished 及 case/repetition 不匹配，避免错误核算。
8. **重复完成结果膨胀质量人口**：拒绝同一完成结果键重复，避免“计划 2 条、计分 3 条”。

报告完整性校验仍依赖本地信任边界，哈希不是对抗性身份认证。恢复与费用逻辑也不代表供应商账单已被外部独立核对。

**额外证据规则修订**：T1 新版回答引用了真实存档和真实 AI 整理窗口，但存档页的旧 effective header 本身不能证明该具体 edition 在 10/18 仍适用。原答案保留 4/5，未将其改写为“伪造”或“已证伪”。现已明确：`eligible=true` 只是本地检索资格；不能替代原生版本链／过渡证据。registry-only 的区间须单独披露，精确现行版证据不足时保留不确定性。同步收紧该 status 的 reason，不改变原有检索窗口。此文档／说明修订**未再次做模型确认**，不覆盖先前原始成绩。[前后快照与说明](post-trial-evidence-clarification/change.json)

C-K 还出现一处较窄的引用覆盖缺口：五条引用未展示新评测的精确小节标题。评分后从已保留原生全文及两个绑定 passage 找到该标题，未证明回答错误、未改变评分；补充核验另存。[标题支持核验](confirmation-title-support-resolution.json) 两个图内点值在当次评分包中仅由本地 claim 条件字段支持，评分未冒称从原生图形独立复核。

## 6. 运行条件、成本与限制

24 次任务使用各自独立目录，OS Seatbelt 拒绝读取仓库、评分控制目录、安装技能／插件和其他任务目录，实际 canary 全部拒绝；全部 assigned 技能执行后字节不变。关闭原生 web、apps、plugins、hooks、multiagent 等入口。初始内置嵌套 sandbox 不可用，因此在外部 OS sandbox 内使用 CLI 的 danger-full-access 模式，不能据这个参数声称没有隔离。

这仍非全主机文件读取白名单，也非 OS 出网白名单：订阅推理通信可用，其他未枚举的主机历史副本未被全面屏蔽。323 个已完成命令的关键路径／网络工具检查没有命中越界读取或外部补资料；这不能证明完全没有信息泄漏。24 条 native error item 均为相同的试验性 feature 警告，未导致任务失败。临时配置已在结束后核对删除。

原生累计用量：input **5,148,852** tokens，其中 cached input **4,291,072**；output **106,034**，其中 reasoning **31,071**。子集不重复相加。任务耗时合计 2,224.389 秒，包含并行，不能当作用户等待时长或稳健延迟比较。使用现有 Codex 订阅身份，没有创建 API key、外部付费目标或 judge API；美元费用为 **unknown/null**，不写零。主观评分由本次分析代理完成，未另行获取供应商账单。

样本刻意覆盖新增功能与可疑边界、仅每题每版一次；不是随机生产分布。确认题为预留新变体，优化代理未获得这些题，但知识主题与本次更新有关。没有统计显著性或总体效果估计，没有长期生产回归证明。评测 harness 也修复了一处预算执行缺口：前 16 次有单次超时与次数上限，但总墙钟预算仅声明；后 8 次加了统一截止执行，保留 runner v1/v2 与变更记录。实际未超过登记总时限，未追加目标调用。
